## Etapa 1 — Troca da seção de comunicação

Tela: não.

Arquivos: mudar `hooks/register.ts`; criar `test/troca.test.ts` (escritor de teste).

O que prova a etapa (cada caso compõe uma lista falsa pelo `on('prompt.compose')` do teste e lê
`await $.prompt.compose()`):
- Variante do Fable: seção `communication` com o texto "# Communicating with the user\n\nYour text output is what the user reads... Before your first tool call, say in a sentence what you're about to do; while working, give brief updates when you find something load-bearing or change direction.\n\nLead with the outcome. ...\n\nWrite code that reads like the surrounding code: match its comment density, naming, and idiom.\nOnly write a code comment to state a constraint the code itself can't show." O resultado não contém "Before your first tool call" nem "brief updates"; contém "Between tool calls, write nothing"; contém o parágrafo "Write code…\nOnly write a code comment…" inteiro, depois do texto do mod.
- Variante do Haiku: "# Text output (does not apply to tool calls)\nAssume users can't see most tool calls or thinking. Before your first tool call, state in one sentence what you're about to do. ... Brief is good — silent is not.\n\nIn code: default to writing no comments. Don't create planning, decision, or analysis documents unless the user asks for them." O resultado não contém "silent is not"; contém o parágrafo "In code: …" inteiro.
- Variante `turn_updates`: "Before you start, say in a line what you're about to do; brief updates while you work help the user follow along. Close with a short recap…". O resultado não contém "Before you start, say"; é exatamente o texto do mod (não há parágrafo de código).
- Prompt curto: "Write code that reads like the surrounding code: match its comment density, naming, and idiom." O resultado é o texto do mod, uma linha em branco, e essa linha.
- As outras seções (`lean_body` shared antes, `memory` session depois) saem com id, texto, escopo e posição iguais; `communication` continua no mesmo lugar e com o mesmo escopo.
- Duas composições da mesma lista dão textos idênticos (o cache do prompt depende disso).
- Caso de borda: parágrafo de código no meio do texto (antes de um parágrafo de narração) é mantido; parágrafo que só menciona "code" no meio da frase não conta como parágrafo de código.

Como fazer:
- No hook de `prompt.compose`: `const r = await next(e)`; devolva `{ sections: r.sections.map(s => s.id === 'communication' ? { ...s, text: trocar(s.text) } : s) }`.
- `trocar(texto)`: separa em parágrafos por linha em branco (`/\n\s*\n/`), guarda os que, sem espaço
  à esquerda, começam por `Write code`, `Only write a code comment` ou `In code:`, e devolve
  `[TEXTO, ...guardados].join('\n\n')`.
- `TEXTO` é uma constante do módulo, exatamente:

```
# Communicating with the user

Your text output is what the user reads; they usually can't see your thinking or the raw tool results. Write it for a teammate who stepped away and is catching up: they don't know the codenames or shorthand you created along the way, and they didn't watch your process unfold.

Between tool calls, write nothing. Text before a tool call is justified only by one of four things: a decision you need from the user before continuing; a finding that changes the direction of the work; the result, when the work is done; an answer to a question the user asked. A message that fits in under a line and is followed by a tool call ("Now the CSS.", "Running the tests.", "Found 4 spots, fixing.") is a caption of what the tool log already shows: don't write it. While you work, silence is a complete answer.

Everything the user needs from this turn, including answers, findings, conclusions and deliverables, goes in the final message of the turn, with no tool calls after it.

Lead with the outcome. Your first sentence after finishing should answer "what happened" or "what did you find". Supporting detail and reasoning come after, for readers who want them.

Being readable and being concise are different things, and readable matters more. Keep output short by being selective about what you include, not by compressing the writing into fragments, abbreviations, arrow chains or jargon. Write in complete sentences with technical terms spelled out.
```

- Não mude ordem nem escopo: a lista com seção `shared` depois de `session` faz o motor ignorar o hook.

## Etapa 2 — Reserva e aviso

Tela: não.

Arquivos: mudar `hooks/register.ts`; criar `test/reserva.test.ts` (escritor de teste).

O que prova a etapa:
- Lista sem `communication` (por exemplo `lean_body` shared, `memory` session): o resultado termina
  numa seção nova de id `calado:communication`, escopo `session`, texto igual ao do mod; as seções
  de antes saem iguais e na mesma ordem.
- Lista com `communication` normal: nenhuma seção nova é acrescentada.
- Marca de narração que sobrou noutra seção (por exemplo `tone` com "Before your first tool call,
  say…"): um aviso aparece (`ui.toast`), e o texto dele cita o nome do mod e o id da seção. Vale
  para cada marca: "Before your first tool call", "Before you start, say", "brief updates",
  "silent is not".
- Segunda composição na mesma sessão, com a marca ainda lá: nenhum aviso novo.
- Lista sem marca nenhuma: nenhum aviso.
- O texto do mod, que contém "brief" em outra forma, não dispara o aviso: a busca roda depois da
  troca e o texto do mod não tem nenhuma das quatro marcas.
- O teste precisa responder ao evento `ui.toast` com um `on('ui.toast', ($, e) => { ... })` que
  guarda `e.text`; sem isso o motor de teste lança erro.

Como fazer:
- Depois da troca da etapa 1, se nenhuma seção tiver id `communication`, acrescente
  `{ id: 'calado:communication', text: TEXTO, scope: 'session' }` no fim.
- Procure as quatro marcas, como texto exato, em todas as seções do resultado. Achou e o estado
  `avisado` é falso: `$.ui.toast('calado: a seção <id> ainda pede narração; o Claude Code mudou o prompt')`
  e grave `avisado` verdadeiro.
- Estado: `import { atom, read, update } from 'claude-code'`;
  `const avisado = atom({ plugin: 'calado', key: 'avisado' } as const, false)`; `await read($, avisado)`
  e `await update($, avisado, () => true)`. Molde: `examples/band.tsx` linhas 1-7 e 29-40 da pasta
  da skill; contrato já em `types/index.d.ts` desde a etapa 0.
- O aviso não pode atrasar nem quebrar a montagem: não espere o toast (`void $.ui.toast(...)`).
